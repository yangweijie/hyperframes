01 · 初衷

为什么要有这个包

逐帧全页截图，
太 慢 了

标准渲染把整页 HTML 每一帧 都交给 Chromium 截图再编码。 背景静止、循环段重复——却要反复重绘、反复编码。 ffmpeg-layer-renderer 的想法很简单：把画面拆成图层， 静态背景只抓一次，动态层预渲染成透明资产，最后用 ffmpeg overlay 合成。

data-composition-src 切层 ProRes 4444 透明资产 ffmpeg overlay 合成 GPU 硬件编码
02 · 遇到问题

踩过的坑

三个拦路虎

overlay: format=yuva420p 被拒 gsap 没随包 bundle headless-shell 启动失败

overlay 滤镜的 format 枚举不认 yuva420p，需改 format=auto 保留 alpha； 包不打包 gsap，要靠 ensureGsapAsset 从 node_modules 复制； Windows 上 chrome-headless-shell 缺失运行库，改用系统 Edge 注入。

03 · 解决后的效果

端到端跑通

更快，且保真

3
切出图层（1 背景 + 2 overlay）
2.9s
composite 合成耗时
~30dB
PSNR vs 整页渲染

背景只预渲染一次，composite 由 ffmpeg 并行 overlay，比逐帧截图快数倍； PSNR 落在官方 30dB 阈值附近，视觉无损。

04 · 如何使用

两条路径

一键导出

# CLI · 只用 ffmpeg 加速路径
npx hyperframes layer-render index.html -o out.mp4 --fps 30

或在 Studio 里点 “Export with FFmpeg” 按钮（engine: layer）， 走图层化渲染——同一引擎，无需改组合结构。
